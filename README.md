# 📸 みんなのおでかけ｜掲載登録フォーム

おでかけナビ本体とは独立した、GitHub Pagesで動く静的サイトです。
本体のコード・デザイン・施設データには一切手を加えていません。

## ファイル一覧と役割

```
minna-no-odekake/
├── index.html          … 紹介者向けの公開フォーム（STEP1: 自分の情報 → STEP2: 紹介スポット → 確認 → 完了）
├── admin.html           … 運営者専用の管理ページ（一覧確認・編集・公開/非公開・削除・完成版JSON出力）
├── assets/
│   ├── style.css        … 共通デザイン（おでかけナビのブランドに合わせた配色・フォント）
│   └── app.js            … 共通ロジック（バリデーション、施設検索、localStorage管理、JSON生成）
├── data/
│   ├── spots.sample.json         … 施設データのサンプル（動作確認用。本番は本体の施設データに差し替え）
│   └── contributors.sample.json  … 公開済み紹介者のサンプル（同上）
└── README.md
```

画像のアップロード・保存機能は実装していません（プロフィール画像・投稿画像とも一切保存しません）。

## データの流れ（GitHub Pagesだけで完結する運用）

GitHub Pagesは静的サイトのため、フォームの送信内容を自動でリポジトリに保存したり、
自動コミットしたりすることはできません。そのため、以下の流れを想定しています。

1. **紹介者** が `index.html` でフォームに入力し、確認画面で送信すると、完了画面に
   「登録内容（JSON）」が表示されます（保存はされず、その場で生成されるだけです）。
2. 紹介者はその内容を **コピー または ダウンロード** し、LINE・メール等で運営者に送ります。
3. **運営者** は `admin.html` を開き、「取り込み」タブに送られてきたJSONを貼り付けて取り込みます。
   （直接手入力で紹介者・紹介投稿を追加することも可能です）
4. 取り込まれたデータは「未公開」の状態で一覧に表示されるので、内容を確認し、
   必要に応じて編集したうえで「公開する」に切り替えます。
5. 「完成版JSON出力」タブで、その時点の全データから `contributors.json` と
   `contributions.json` を書き出し、ダウンロードします（差分ではなく常に全件です）。
6. ダウンロードした2つのファイルを、おでかけナビ本体のリポジトリの然るべき場所
   （例：`/data/contributors.json` と `/data/contributions.json`）に手動でアップロードします。

これにより、GitHubリポジトリの容量を増やす画像データを持たずに運用できます。

管理データは運営者のブラウザの `localStorage` に保存されます。運営者が複数人いる場合や
別の端末で作業したい場合は、`admin.html` の「取り込み」機能を使って完成版JSONを
貼り付け直すことで、同じ状態を別の端末でも再現できます。

## 完成版JSONの使い方

- `contributors.json` … 紹介者情報（表示名・Instagram URL・紹介文・公開状態）の全件
- `contributions.json` … 紹介投稿情報（紹介者ID・施設ID・投稿URL・コメント・訪問日・公開状態）の全件
- どちらも管理画面の「現在の全データ」がそのまま出力されるため、削除した紹介者・投稿は
  次回の出力に含まれません。

## フォームの流れ（全面リニューアル版）

インスタグラマーが「タップ→タップ→貼り付け→送信」で1〜2分で完了できるよう、
1画面1テーマのウィザード形式に全面刷新しました。

1. **ウェルカム画面** — 説明とCTAのみ。入力項目なし。このブラウザで前回登録済みの
   場合は「👋 ○○ママさん／またスポットを紹介しますか？」と表示し、Instagram情報の
   再入力なしでSTEP2（スポット）へ直接進めます。
2. **STEP1 Instagram** — Instagram URLのみ入力。入力すると自動でユーザー名を抽出し、
   「✓ 表示名 ／ Instagram：@ユーザー名」を表示します。表示名はユーザー名がそのまま
   初期値になり、変更したい場合だけ「表示名を編集する」から任意で変更できます。
   プロフィール紹介文の入力は廃止し、内部データとしては空文字で保持します
   （後から管理画面で編集可能）。**紹介者IDはユーザーには入力させず、システムが
   自動発行**します。
3. **STEP2 スポット** — 施設名を1文字入力するとカード形式の候補が表示され、タップで
   選択します（自由入力不可、既存施設データからのみ選択）。
4. **STEP3 投稿URL** — Instagram投稿URLを貼り付け。
5. **STEP4 ひとこと** — コメント（任意・300文字）と訪問日（任意）。
6. **STEP5 確認** — カード形式で内容をまとめて表示し、「この内容で送る」で送信。
7. **STEP6 完了** — 「🎉 ありがとうございます！」と表示し、初回登録者には紹介者ID
   （例：`creator_024`）を表示します（次回このブラウザで開いた際は自動的に紐づきます）。
   「もう1スポット紹介する」でInstagram情報の再入力なしにSTEP2からやり直せます。
   送付用のJSONは `<details>` の中に折りたたんで表示し、通常は見えないようにしています。

各STEP画面には「← もどる」ボタンと5つのドットによる進捗表示を常設しています。

## 複数デバイスでの同一人物の扱い

紹介者IDの手入力を廃止したため、同じ人が別のスマホ・別のブラウザから登録すると、
紹介者IDが新しく発行されてしまう場合があります。これに対応するため、管理画面の
「取り込み」と、フォーム側の「一括出力」機能の両方で、**Instagram URLが完全一致
する紹介者が既にいる場合は自動的に統合**し、紐づく紹介投稿のcontributorIdも
正しい方のIDへ付け替えるようにしています。表示名などを直したい場合は管理画面の
「編集」から調整してください。

## 一括出力ボタン（管理者が自分で入力する場合）

確認画面には「登録する」の他に「一括出力（管理者用）」ボタンがあります。運営者自身が
このフォームでデータを入力する場合、このボタンを押すと、既存の公開データ
（`contributors.json` / `contributions.json`）に今回の入力を加えた完成版JSONが、
公開状態 (`published: true`) でその場に出力されます。通常の「登録する」ボタン
（紹介者から運営者への送付フロー・未公開扱い）とは用途が異なります。

## 施設データとの連携（要調整）

完了画面の「おでかけナビを見る」ボタンは、本体サイトへのリンクとして仮に `../`
（このフォームの1つ上の階層）を指定しています。実際の本体サイトのURLに合わせて
`index.html` 内の `id="btn-see-navi"` の `href` を書き換えてください。

紹介スポットの選択は、既存のおでかけナビ本体が持つ施設データを検索・選択する方式で、
このフォーム側で施設名や住所などを複製・編集することはありません。保存されるのは
選択した施設の `spotId` のみです。

`assets/app.js` の先頭にある `SPOTS_DATA_URLS` に、本体が使っている施設データの
実際の公開パス（例：`https://your-domain/odekake-navi/data/spots.json` など）を
追加・調整してください。取得できるまでは同梱の `data/spots.sample.json` で
動作確認ができます。データの各項目名（`id` / `name` / `area` など）が本体と異なる場合は、
`loadSpots()` 内のマッピング部分を実際のフィールド名に合わせて調整してください。

同様に、`CONTRIBUTORS_DATA_URLS` は「登録済み紹介者を選ぶ」プルダウンに表示する
公開済み紹介者一覧の参照先です。運営者が `admin.html` から出力した `contributors.json` を
本体リポジトリにアップロードした後のパスを指定してください。

## GitHub Pagesへの配置方法

1. このフォルダ（`minna-no-odekake/`）を、おでかけナビ本体とは別のリポジトリ
   （または本体リポジトリ内の独立したサブディレクトリ）に配置します。
2. リポジトリのSettings → Pages で公開を有効にします。
3. 紹介者には `index.html` のURLのみを共有してください。
4. `admin.html` にはパスワードロックを付けています（初期パスワード：`qwe123`。
   `admin.html` 内 `ADMIN_PASSWORD` で変更できます）。ただしブラウザ側だけで
   照合する簡易的なものなので、ページのソースを見れば誰でもパスワードが分かります。
   本格的な認証ではなく「うっかりたどり着いた人が編集できないようにする」ための
   簡易ロックです。検索エンジンへのインデックスやSNSでの共有は避けてください。
5. `index.html` の一番下に、管理画面への目立たないリンク（「・」の1文字）を
   設置しています。運営者はこのリンクから `admin.html` に入れます。

## 今回変更していない既存ファイル

おでかけナビ本体のリポジトリ・ファイルには一切手を加えていません。本体が持つ以下の機能は
すべてそのままです。

- 「今日どこ行く？」3問質問フロー
- 年齢フィルター・天気・距離・駐車場
- お気に入り・「行ったよ」機能
- 施設検索・施設詳細
- アフィリエイトリンク
- PWA対応・localStorage活用（本体側の既存キー）
- SEO設定

このフォームは本体の `localStorage` キーとは別の名前空間
（`odekake_mnO_` で始まるキー）を使用しているため、本体の動作に影響しません。

## 将来の「👣 行ったよ！」機能との分離

今回のデータ（`contributors` / `contributions`）は「紹介者によるInstagram投稿の紹介」専用です。
将来追加予定の一般ユーザーによる体験投稿機能（「行ったよ！」）とは、データ構造・保存先とも
完全に分離されており、混同しない設計になっています。
